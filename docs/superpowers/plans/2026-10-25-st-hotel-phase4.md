# ST Hotel ໄລຍະ 4 (ແມ່ບ້ານ + ບຳລຸງຮັກສາ) — ແຜນການສ້າງ

> ເຮັດແບບ Native ໃນ session ດຽວ (ເຈົ້າຂອງສັ່ງ "ເລີມໄລຍະ 4"): ແຕ່ລະ Task = ເທສລົ້ມກ່ອນ → ໂຄ້ດ → ເທສຜ່ານ → commit. **ຍັງບໍ່ push / ບໍ່ deploy.**

**Goal:** ກະດານສະຖານະຫ້ອງ, ງານແມ່ບ້ານຕໍ່ຄົນ (ໃຊ້ໄດ້ໃນມືຖື), ກວດຫ້ອງ (inspect), ແຈ້ງຊ່ອມ + ປິດຫ້ອງຊົ່ວຄາວ (OOO), ຂອງລືມ, ຕັດສະຕ໊ອກຜ້າ/ເຄື່ອງໃຊ້ໃນຫ້ອງ.
**Spec:** ການອອກແບບຂໍ້ 5 (`htHk` `htMt` `htLf`), 6, 7.4. ໂມດູນ `htHk` (ເປີດ/ປິດໄດ້ — ປິດແລ້ວເຊື່ອງໜ້າ).

## ການຕັດສິນຂອງຜູ້ສ້າງ
- ຕຳແໜ່ງ: ໃຊ້ບົດບາດເດີມ — `storekeeper` ໃນໂໝດໂຮງແຮມ ເອີ້ນວ່າ **ແມ່ບ້ານ & ນາຍສາງຜ້າ**, `purchasing` ເອີ້ນວ່າ **ຊ່າງ & ຈັດຊື້** (ເຈົ້າຂອງຕິກສິດລາຍຄົນເພີ່ມໄດ້).
- ງານແມ່ບ້ານ: ອາເຣ `htTask` (ບໍ່ໃຊ້ຊື່ `htHk` ເພື່ອບໍ່ປົນກັບຊື່ໂມດູນ), id ຕາຍຕົວ `hk_<ຫ້ອງ>_<ວັນ>_<ປະເພດ>` → ສ້າງຊ້ຳ/ສອງເຄື່ອງບໍ່ຊ້ອນ.
- ກວດຫ້ອງ (supervisor inspect) ປິດເປັນຄ່າເລີ່ມຕົ້ນ (`hkInspect=false`): ເຮັດແລ້ວ → ຫ້ອງສະອາດ. ເປີດແລ້ວ: ເຮັດແລ້ວ → ລໍກວດ → ຜ່ານ=inspected / ບໍ່ຜ່ານ=ກັບໄປເຮັດໃໝ່.
- ຜ້າ/ເຄື່ອງໃຊ້: ກຳນົດ "ຊຸດຕໍ່ຫ້ອງ" (ວັດຖຸດິບ+ຈຳນວນ) ໃນຕັ້ງຄ່າ; ຕອນງານ clean ສຳເລັດ ຕັດສະຕ໊ອກ 1 ເທື່ອ (ບໍ່ຕັດຊ້ຳ). ເບີກໃຊ້ເອງໄດ້ (`htHkUse`). ມິນິບາ: ຄິດເງິນຜ່ານ "ເພີ່ມຄ່າໃຊ້ຈ່າຍ" ໃນບິນຫ້ອງ (ໄລຍະ 3) — ຍັງບໍ່ມີລາຄາມິນິບາອັດຕະໂນມັດ.
- ປິດຫ້ອງຊ່ອມ (OOO) ຖ້າຫ້ອງມີການຈອງທັບ → ບໍ່ໃຫ້ (ຕ້ອງຍ້າຍກ່ອນ).

## Global Constraints
- ແຖວມີ `id`+`upd`; ບໍ່ລຶບ (ໃຊ້ `void`/status). ອາເຣໃໝ່ `htTask htMt htLf` ຕ້ອງໃສ່ `Code.gs mergeDocs_` + `app.js BR_RESET` + `htInit`.
- ສິດ act ໃໝ່: `htHkDo` (ເຮັດງານ/ປ່ຽນສະຖານະ/ແຈ້ງຊ່ອມ/ຂອງລືມ), `htHkAssign` (ມອບງານ/ກວດ/ຈຳໜ່າຍຂອງລືມ), `htMtFix` (ແກ້ງານຊ່ອມ). view ໃໝ່ `htHk`.
- Check-out / ຍ້າຍຫ້ອງ ສ້າງງານ clean ຂອງຫ້ອງເກົ່າ ໂດຍອັດຕະໂນມັດ.
- ເທສເກົ່າທັງໝົດຕ້ອງຜ່ານ.

## Review Focus
1. ສ້າງງານຊ້ຳບໍ່ໄດ້; ເຮັດງານຊ້ຳ ບໍ່ຕັດສະຕ໊ອກຊ້ຳ.
2. ຫ້ອງມີແຂກພັກ ບໍ່ຖືກປ່ຽນເປັນ "ສະອາດ/ກວດແລ້ວ" ໂດຍບໍ່ຕັ້ງໃຈ (stay task ບໍ່ປ່ຽນ hk).
3. OOO ບລັອກການຈອງໃໝ່ ແລະ ປົດເມື່ອຊ່ອມແລ້ວ; ຫ້ອງທີ່ມີການຈອງທັບ ປິດບໍ່ໄດ້.
4. ບໍ່ມີສິດ → ເຮັດບໍ່ໄດ້; ໂມດູນປິດ → ໜ້າຫາຍ.
