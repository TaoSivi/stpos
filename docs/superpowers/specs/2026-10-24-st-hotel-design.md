# ST Hotel — ເອກະສານອອກແບບ (ບ້ານພັກ · ໂຮງແຮມ · ລີສອດ)

ວັນທີ: 2026-10-24 · ສະຖານະ: ລໍເຈົ້າຂອງອະນຸມັດ · ຜູ້ຂຽນ: Claude

## 1. ຈຸດປະສົງ ແລະ ເຫດຜົນ
ເຈົ້າຂອງ (TaoSivi) ຢາກເພີ່ມລະບົບຈັດການທີ່ພັກ ເຂົ້າໃນຕະກູນ ST POS ແບບດຽວກັບ ST Mart: **ຂະໜາດໃຫຍ່** (ໂຮງແຮມ/ລີສອດ ທີ່ມີຮ້ານອາຫານ, ບາ, ແມ່ບ້ານ, ບໍລິການເສີມ) ແຕ່ **ແຍກເປັນໂມດູນເປີດ/ປິດໄດ້** ເພື່ອໃຫ້ບ້ານພັກນ້ອຍປິດສ່ວນທີ່ບໍ່ໃຊ້. ເຈົ້າຂອງຕິກ 74 ໃນ 78 ຟັງຊັນຈາກລາຍການ `ST Hotel/ST Hotel - ລາຍການໂມດູນ.html`.

**ເຈົ້າຂອງຕັດອອກ (ບໍ່ເຮັດ):** b10 Channel Manager API ເຕັມ · i6 ແຂກຕື່ມຂໍ້ມູນກ່ອນມາ · j3 ພາສາໄທ/ຈີນ · j7 AI.

## 2. ເປົ້າໝາຍ / ບໍ່ແມ່ນເປົ້າໝາຍ / ສິ່ງທີ່ຫ້າມເກີດ
**ເປົ້າໝາຍ**
- ແອັບດຽວ (`ST Hotel`) ຄຸມ: ຫ້ອງ+ລາຄາ → ການຈອງ+ປະຕິທິນ → check-in/out → ບິນຫ້ອງ (folio) → ແມ່ບ້ານ → ຮ້ານອາຫານ/ບາ/ບໍລິການ ຕໍ່ບິນຫ້ອງ → ລາຍງານ.
- ໃຊ້ໂຄ້ດ ST POS ຕໍ່ (ຮ້ານອາຫານ/ບາ, ສະຕ໊ອກ, ຈັດຊື້, ກະ, ລາຍຈ່າຍ, Audit, ຫຼາຍສາຂາ, ອອບລາຍ, ສອງພາສາ).
- ບ້ານພັກນ້ອຍໃຊ້ໄດ້ ໂດຍປິດໂມດູນ ແລະ ບໍ່ເຫັນເມນູທີ່ບໍ່ກ່ຽວ.
**ບໍ່ແມ່ນເປົ້າໝາຍ:** Channel Manager API · ພາສາໄທ/ຈີນ · AI · ການຍື່ນພາສີອັດຕະໂນມັດ.
**ຫ້າມເກີດ (ເຖິງເຮັດໄດ້ກໍຖືວ່າລົ້ມເຫຼວ):** ຈອງຫ້ອງຊ້ອນກັນ · ບິນຫ້ອງຄິດເງິນຊ້ຳ/ຂາດ ຫຼັງ night audit ຮັນສອງເທື່ອ · ຄືນເງິນ/ປັບບິນໂດຍບໍ່ມີ PIN + Audit · ເຮັດໃຫ້ ST POS ຮ້ານອາຫານ / ST Mart ພັງ.

## 4. ຂໍ້ຈຳກັດ
- ໄຟລ໌ດຽວ `index.html` vanilla JS; ຂໍ້ມູນທັງໝົດຢູ່ໃນ `state` (JSON ກ້ອນດຽວ sync ກັບ server). ອາເຣໃໝ່ທີ່ແຕ່ລະເຄື່ອງຂຽນພ້ອມກັນ ຕ້ອງມີ `id` + `upd` ແລະ ໃສ່ໃນ `mergeDocs_` (`Code.gs`) + `BR_RESET` (`server/app.js`) ເພື່ອບໍ່ໃຫ້ຂຽນທັບກັນ.
- ຂໍ້ມູນລຶບ (ຍົກເລີກການຈອງ) ຕ້ອງ **ໝາຍສະຖານະ** ບໍ່ລຶບແຖວ — ບໍ່ດັ່ງນັ້ນ merge ຈະເຮັດໃຫ້ແຖວກັບມາ (ເຄີຍເຈິກັບ "ບິນທີ່ພັກ").
- ຕ້ອງໃຊ້ໄດ້ຕອນເນັດຫຼຸດ (ໜ້າຈອງ/ເຊັກອິນ/ບິນຫ້ອງ ອ່ານ-ຂຽນໃນເຄື່ອງ ແລ້ວ sync).
- ຊື່ຟັງຊັນໃໝ່ໃຊ້ prefix `ht` (ກວດແລ້ວ ບໍ່ຊ້ຳ). ຊື່ ການຈອງໃນ state ໃຊ້ `bookings` (ບໍ່ຊ້ຳກັບ `resv` ຈອງໂຕະເດີມ).
- ຕ້ອງຜ່ານເທສເກົ່າທັງໝົດ (17 ຊຸດ browser + server) + ເທສ ST Mart.

## 5. ຮູບແບບຂໍ້ມູນ (ຕັດສິນໃຈ: ຂອງຜູ້ສ້າງ)
ອາເຣລະດັບເທິງໃນ `state` (ທຸກແຖວມີ `id`, `upd`):
- `htTypes` ປະເພດຫ້ອງ `{id,name,cap,beds,amen[],img,baseRate,extraAdult,extraChild,extraBed}`
- `htRooms` ຫ້ອງ `{id,no,floor,zone,type,hk:'clean|dirty|inspected|ooo',ooo:{from,to,why}}`
- `htRates` ກົດລາຄາ `{id,name,from,to,days[0-6],type|'*',price,plan,prio}` — ກົດທີ່ຊ່ວງວັນແຄບ/prio ສູງຊະນະ; ບໍ່ມີກົດ = `baseRate`
- `htPlans` ແຜນລາຄາ `{id,name,breakfast,refundable,adj%}`
- `htGuests` ແຂກ `{id,name,nat,idType,idNo,phone,email,vip,black,notes,photo?}`
- `htBookings` ການຈອງ `{id,no,guest,src,status:'tent|conf|in|out|cancel|noshow',lines:[{room|type,from,to,adults,kids,plan,rate[]}],dep,policy,notes,folio,ext?}`
- `htFolios` ບິນຫ້ອງ `{id,booking,status:'open|closed',lines:[{id,ts,dept:'room|fnb|svc|fee|tax|adj',desc,qty,amt,ref,by,void}],pays:[{id,ts,amt,ccy,rate,method,by}]}`
- `htSvc` ບໍລິການ/ກິດຈະກຳ/ເຊົ່າ `{id,name,dept,price,unit,res?}` + `htSvcRes` (ຈອງບໍລິການ: ສະປາ, ທົວ, ສະລອຍນ້ຳ, ຫ້ອງປະຊຸມ)
- `htHk` ງານແມ່ບ້ານ · `htMt` ແຈ້ງຊ່ອມ · `htLf` ຂອງລືມ
- `htAcc` ບັນຊີບໍລິສັດ/ຕົວແທນ (city ledger) `{id,name,terms,commission%}`
- `htCfg` (ວັນ/ເວລາ check-in/out, ຊົ່ວໂມງ night audit, ພາສີ/ຄ່າບໍລິການ/ຄ່າທຳນຽມ, ນະໂຍບາຍຍົກເລີກ, iCal feeds, ວັນທີທຸລະກິດ `bizDate`)

## 6. ວິທີເຮັດວຽກຫຼັກ
- **ລາຄາຕໍ່ຄືນ** = ກົດຊະນະ (`htRates`) ແລ້ວ × ແຜນ + ຄົນ/ຕຽງເພີ່ມ − ສ່ວນຫຼຸດ/ໂຄ້ດ; ຫຼາຍສະກຸນ ຄິດຖານເປັນກີບ ສະແດງ ฿/$ ຕາມອັດຕາແລກປ່ຽນທີ່ມີແລ້ວ. ຄືນເກົ່າ **ຕິດຕາຍ** ໃນ `lines[].rate[]` ຕອນຈອງ (ປ່ຽນກົດພາຍຫຼັງ ບໍ່ກະທົບການຈອງເກົ່າ).
- **ວ່າງຫຼືບໍ່:** ຫ້ອງ × ຄືນ ຕ້ອງບໍ່ມີການຈອງ status ≠ cancel/noshow/out ຊ້ອນ ແລະ ບໍ່ຢູ່ໃນຊ່ວງ OOO. ກວດທັງຕອນສ້າງ, ແກ້, ຍ້າຍຫ້ອງ, ແລະ ຕອນນຳເຂົ້າ iCal. ຈອງລະດັບປະເພດ (ຍັງບໍ່ກຳນົດຫ້ອງ) ນັບຕາມຈຳນວນຫ້ອງຂອງປະເພດ.
- **Night audit** (ມື້ປິດ): ຕາມ `bizDate` ລົງຄ່າຫ້ອງ+ພາສີ ຂອງທຸກການຈອງ in-house ເທື່ອລະຄືນ ໂດຍມີ key `booking+date` ຮັບປະກັນບໍ່ລົງຊ້ຳ; ເລື່ອນ `bizDate`; ເຮັດມື້ໃດກໍໄດ້ ຖ້າລືມ (catch-up). ປິດບໍ່ໄດ້ຖ້າມີ check-out ທີ່ຍັງຄ້າງບິນ (ເຕືອນ).
- **ຮ້ານອາຫານ→ບິນຫ້ອງ:** ວິທີຈ່າຍໃໝ່ "ຕິດບິນຫ້ອງ" ໃນໜ້າຮັບເງິນເດີມ: ເລືອກແຂກ in-house → ບັນທຶກແຖວ `dept:'fnb'` ໃນ folio (ອ້າງເລກບິນ POS) ແລະ ບິນ POS ຖືກໝາຍຈ່າຍແບບ `room` (ບໍ່ນັບເປັນເງິນສົດໃນກະ). ຍົກເລີກ/Void ບິນ POS ຕ້ອງຖອນແຖວໃນ folio ນຳ.
- **ແຍກບິນ/ຈ່າຍບາງສ່ວນ:** folio ແຍກເປັນຫຼາຍ "ຜູ້ຈ່າຍ" ໂດຍໝາຍແຖວ `payer`.
- **Check-out:** ຫັກມັດຈຳ → ຮັບເງິນສ່ວນທີ່ເຫຼືອ → ໃບເສັດ/ໃບກຳກັບ → ຫ້ອງເປັນ `dirty` + ສ້າງງານແມ່ບ້ານ.
- **iCal:** ສົ່ງອອກ `.ics` ຕໍ່ຫ້ອງ (URL ມີ token ລັບຕໍ່ຫ້ອງ) · ນຳເຂົ້າ: server ດຶງ URL ຂອງ OTA (browser ດຶງເອງບໍ່ໄດ້ ເພາະ CORS) ແລ້ວສ້າງ "ຊ່ວງບລັອກພາຍນອກ" (`ext`) ຕໍ່ຫ້ອງ; ເຮັດຮອບ 10 ນາທີ ຕາມ cron ທີ່ມີ; ບໍ່ສ້າງແຂກຈາກ iCal. ສະແດງວ່າ "ອັບເດດລ່າສຸດ HH:MM".
- **ໜ້າຂໍຈອງອອນລາຍ:** ໜ້າສາທາລະນະ (ໂໝດລູກຄ້າແບບ QR ທີ່ມີແລ້ວ) ສະແດງຈຳນວນຫ້ອງວ່າງ+ລາຄາ ແລະ ຮັບ "ຄຳຂໍ" ເປັນ `tent` ໃຫ້ຜູ້ຈັດການຢືນຢັນ. Server ກັນສະແປມ (ຈຳກັດຕໍ່ IP) ແລະ **ບໍ່ສົ່ງຂໍ້ມູນແຂກຄົນອື່ນ** ອອກຫານອກ.
- **ຫຼາຍທີ່ພັກ:** ໃຊ້ລະບົບສາຂາເດີມ (ແຕ່ລະສາຂາ=ທີ່ພັກ, ປະເພດຫ້ອງ+ລາຄາກາງ ສົ່ງຈາກສາຂາແມ່ຄືກັບເມນູ; ລາຍງານລວມ).
- **ສິດ:** view ໃໝ່ (`htRooms`,`htCal`,`htDesk`,`htFolio`,`htHk`,`htMt`,`htRep`) + act ໃໝ່ (`htBook`,`htCheckin`,`htRate`,`htPost`,`htVoid`,`htAudit`,`htGuestId`). ບົດບາດ: ເຈົ້າຂອງ, ຜູ້ຈັດການ, ຕ້ອນຮັບ, ແມ່ບ້ານ, ຮ້ານອາຫານ/ບາ, ຊ່າງ, ບັນຊີ. **ເບິ່ງຮູບ passport/ເລກບັດ ແຍກເປັນສິດ `htGuestId`** (ຕ້ອນຮັບ+ຜູ້ຈັດການ+ເຈົ້າຂອງ); ທຸກການເບິ່ງ ບັນທຶກ Audit.
- **ໂມດູນເປີດ/ປິດ** (ໃຊ້ `MODULES` ເດີມ): `htCore` (ຫ້ອງ+ຈອງ+ບິນຫ້ອງ — ປິດບໍ່ໄດ້) · `htHk` ແມ່ບ້ານ+ບຳລຸງ · `htSvc` ບໍລິການ/ທົວ/ເຊົ່າ · `htSpa` · `htPool` · `htEvent` · `htFnb` (ຮ້ານອາຫານຕໍ່ບິນຫ້ອງ + KDS) · `htIcal` · `htOnline` ໜ້າຂໍຈອງ · `htAcc` ບັນຊີບໍລິການ · `htRetail` ມິນິມາດ. ປິດແລ້ວ ເມນູ/ປຸ່ມ/ລາຍງານທີ່ກ່ຽວຖືກເຊື່ອງ.
- **ແອັບ/ພາສາ:** ຂະຫຍາຍ `ST Mart/build.py` ເປັນ `build.py --app mart|hotel`; ສອງພາສາ ເພີ່ມຄຳແປໜ້າໃໝ່ (ຮູບແບບ `MT_RAW` ເດີມ); ສາທິດ `?demo=hotel` ມີຂໍ້ມູນຕົວຢ່າງ (ຂອງຜູ້ສ້າງ: 24 ຫ້ອງ 4 ປະເພດ + ການຈອງຕົວຢ່າງ).

## 7. ໄລຍະສ້າງ (ແຕ່ລະໄລຍະ ທົດສອບ + commit ກ່ອນໄປຕໍ່)
1. **ຫ້ອງ + ລາຄາ:** `BIZ.hotel`, ປະເພດຫ້ອງ, ຫ້ອງ, ກົດລາຄາ/ແຜນ, ພາສີ, ເຄື່ອງຄິດລາຄາ (+ເທສຫົວໃຈ), ສະແດງ ฿/$, build `--app hotel`, demo.
2. **ປະຕິທິນ + ການຈອງ:** ຕາຕະລາງ ຫ້ອງ×ວັນ, ສ້າງ/ແກ້/ຍົກເລີກ, ກັນຊ້ອນ, ກຸ່ມ, ມັດຈຳ+ນະໂຍບາຍ, ແຫຼ່ງຈອງ, ຂໍ້ຄວາມຢືນຢັນ, no-show.
3. **ຕ້ອນຮັບ + ບິນຫ້ອງ:** ທະບຽນແຂກ, ຮູບ ID, check-in/out, ຍ້າຍ/ຕໍ່/ອອກກ່ອນ, folio, ເພີ່ມຄ່າ, ແຍກບິນ, ບັນຊີບໍລິສັດ, ໃບແຈ້ງໜີ້/ໃບກຳກັບ A4, night audit, ລາຍງານແຂກຕ່າງປະເທດ.
4. **ແມ່ບ້ານ + ບຳລຸງ:** ກະດານສະຖານະ, ງານຕໍ່ຄົນ (ມືຖື), ແຈ້ງຊ່ອມ, ຂອງລືມ, ຕັດສະຕ໊ອກຜ້າ/ມິນິບາ.
5. **ຮ້ານອາຫານ/ບາ/ບໍລິການ → ບິນຫ້ອງ:** "ຕິດບິນຫ້ອງ", ລາຍຊື່ອາຫານເຊົ້າ, room service, ຊັກລີດ, ທົວ/ເຊົ່າ, ສະປາ, ສະລອຍນ້ຳ, ຫ້ອງປະຊຸມ, ມິນິມາດ, QR ໃນຫ້ອງ.
6. **ລາຍງານ + ຊ່ອງທາງ + ອື່ນໆ:** Occupancy/ADR/RevPAR, ຄາດການ 30 ວັນ, ຄ່ານາຍໜ້າ, iCal, ໜ້າຂໍຈອງອອນລາຍ, ສອງພາສາ, ແບບຟອມຄວາມເຫັນ.
7. **ເຊື່ອມອຸປະກອນພາຍນອກ (ເຈົ້າຂອງຕິກ ແຕ່ຕ້ອງຮູ້ຍີ່ຫໍ້ກ່ອນ):** ເຄື່ອງອ່ານບັດ/ກຸນແຈ (j5) ແລະ payment gateway (j6). ຂ້ອຍສ້າງ "ຈຸດເຊື່ອມ" (interface + ບັນທຶກ) ໃນໄລຍະ 3/5 ແລະ ເຮັດ driver ຈິງເມື່ອມີຍີ່ຫໍ້ + ເອກະສານ API. **ບໍ່ສັນຍາວ່າເຮັດໄດ້ກ່ອນເລືອກຍີ່ຫໍ້.**

## 8. ການທົດສອບ
- ເທສໃນໜ້າ (ໄວ, ບໍ່ຕ້ອງ UI): ເຄື່ອງຄິດລາຄາ (ລະດູການ/ທ້າຍອາທິດ/ແຜນ/ຄົນເພີ່ມ), ກວດວ່າງ/ຊ້ອນ, night audit ຮັນຊ້ຳບໍ່ເພີ່ມ, folio ຍອດ = ແຖວ − ຈ່າຍ, ຍົກເລີກ/ມັດຈຳ.

- ເທສເກົ່າທັງໝົດຕ້ອງຍັງຜ່ານ.

## 9. ສິ່ງທີ່ເຈົ້າຂອງຕ້ອງໃຫ້ / ຕັດສິນ (ຄ້າງຢູ່)

4. ຍີ່ຫໍ້ເຄື່ອງອ່ານບັດ/ກຸນແຈ ແລະ payment gateway (ກ່ອນໄລຍະ 7).
